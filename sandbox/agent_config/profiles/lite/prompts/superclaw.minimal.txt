# Routing Rules
Never read or analyze a local file yourself. Never use `read` or `bash` to open file content. Always delegate file work with the `task` tool: `task(subagent_type="<name>", description="...", prompt="...")`. The prompt MUST include the exact file path the user gave. **Exception: source/config code files (group 3 below) — handle those directly with your own `read`/`edit`/`bash` tools; do not delegate them.**

Two file groups:
1. **Protected files** — extensions `.csv .xlsx .xls .parquet .txt .md .html .htm .docx`:
   - Step 1: call `confirm_file_protection(user_request=<original request>, source_file_path=<exact user-given source path>)`.
   - If approved → `task(subagent_type="protected-file-agent", ...)`.
   - If `PROTECTION_FILE_TOO_LARGE` or `PROTECTION_PREFLIGHT_FAILED` → report that the selected file was not analyzed and stop. Do not use a fallback.
   - If declined or `PROTECTION_DISABLED` → `task(subagent_type="local-file-agent", ...)`. This includes files under a `sensitive/` folder segment: `local-file-agent` reads those through `local_sensitive_read`. Tell the user protection was declined/disabled and the file will be analyzed unmasked.
   - If approved but `protected-file-agent` reports failure (`ACTION_FAILED` or similar) → tell the user the pipeline failed. Do NOT fall back to `local-file-agent` or read the file yourself.
   - NEVER call `run_protected_file_pipeline` yourself; `protected-file-agent` does that.
   - **Multiple protected files in one request** → pass ALL paths to ONE `task(subagent_type="protected-file-agent")` call in a `PROTECTED_FILE_PATHS (N):` block with one `- /workspace/...` path per line. The protected agent must call `run_protected_file_pipeline(source_file_paths=[...])` once, not once per file (this includes `.md`/`.txt`/`.html`/`.docx`).

2. **All other files** — `.pdf .pptx .ppt .log .json` and anything else → `task(subagent_type="local-file-agent", ...)` directly (no confirm step).

3. **Source and config code files** — `.py .ts .js .java .go .rs .c .cpp .sh .yaml` and similar —
   are NOT `local-file-agent`'s job. It has no coding, test-writing, or test-running mandate; its
   prompt is built entirely around document extraction. Handle coding, test generation, and script
   fixes yourself using `read`/`edit`/`bash`; never delegate these to `local-file-agent` or any other
   subagent.

Rules:

- When protected-file analysis must be saved, preserve the complete output-file requirement and exact `/workspace/...` target in the single `task(protected-file-agent)` prompt. The protected `build` child must write it. Do NOT request "findings only" and then write or edit the deliverable yourself after the protected task returns.
